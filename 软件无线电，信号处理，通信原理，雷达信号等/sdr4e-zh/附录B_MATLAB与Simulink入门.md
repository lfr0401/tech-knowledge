# 附录B MATLAB与Simulink入门

你将使用MATLAB和Simulink进行本书中的实验和开放式设计项目。本附录作为MATLAB的简要复习，因为你应该以前使用过它。然而，如果你没有丰富的Simulink经验，本附录将向你展示如何开始使用该工具。请注意，本附录的MATLAB部分主要基于[1]中呈现的MATLAB文档，Simulink部分基于[2]中呈现的Simulink基础教程，但在这里我们提取最重要和最基本的概念，以便你在阅读本附录后可以快速开始。关于这两个产品的更多信息，建议参考[1]和[2]。

## B.1 MATLAB简介

MATLAB广泛应用于应用数学的所有领域、大学的教育和研究以及工业界。MATLAB代表矩阵实验室（Matrix Laboratory），该软件围绕向量和矩阵构建。因此，这使得该软件特别适用于解决线性代数问题，也适用于求解代数和微分方程以及数值积分。MATLAB拥有一组图形工具，能够生成高级GUI和二维及三维数据图。MATLAB还有几个工具箱，可用于执行通信、信号处理、图像处理、优化和其他专门操作。

MathWorks创建了一个优秀的在线教程来复习基础和高级概念，并提供讲师主导的教程来展示MATLAB的各种功能。可以在 https://matlabacademy.mathworks.com 找到。

## B.2 有用的MATLAB工具

本节介绍查找错误的一般技术，以及使用自动代码分析功能来检测MATLAB代码中可能需要改进的区域。特别是，将介绍编辑器中的MATLAB调试器功能以及等效的命令窗口调试函数。

调试是你隔离和修复代码问题的过程。调试有助于纠正两种错误：

- **语法错误**：例如，拼写错误的函数名或遗漏括号。
- **运行时错误**：这些错误通常是算法性质的。例如，你可能修改了错误的变量或错误地编写了计算。运行时错误通常在M文件产生意外结果时显现。运行时错误很难追踪，因为当错误强制返回到MATLAB基础工作区时，函数的本地工作区会丢失。

### B.2.1 代码分析和M-Lint消息

MATLAB可以检查你的代码是否存在问题，并通过消息推荐修改以最大化性能和可维护性，这些消息有时被称为M-Lint消息。术语lint是给与其他编程语言（如C）一起使用的类似工具的名称。在MATLAB中，M-Lint工具为M文件中它确定具有改进潜力的每一行显示一条消息。例如，一个常见的M-Lint消息是变量已定义但从未在M文件中使用。

你可以使用三种不同的方式检查编码问题，所有这些方式都报告相同的消息：

- 在工作时在编辑器中持续检查代码。查看M-Lint消息并根据消息修改你的文件。消息会自动持续更新，这样你就可以看到你的更改是否解决了消息中指出的问题。有些消息提供扩展信息、自动代码更正或两者兼有。
- 为现有MATLAB代码文件运行报告：从编辑器中的文件，选择工具 > 代码分析器 > 显示代码分析器报告。
- 为文件夹中的所有文件运行报告：在当前文件夹浏览器中，单击操作按钮，然后选择报告 > 代码分析器报告。

对于每条消息，查看消息和相关代码，以便通过以下过程根据消息对代码本身进行更改：

- 单击行号以在编辑器/调试器中打开该M文件的该行。
- 查看报告中的M-Lint消息并根据消息更改M文件中的代码。
- 注意，在某些情况下，你不应该根据M-Lint消息进行任何更改，因为M-Lint消息不适用于该特定情况。M-Lint不能提供关于每种情况的完美信息。
- 保存M文件。如果你进行了可能引入错误的重大更改，请考虑将文件保存为不同的名称。然后你可以在解决更新文件的问题时参考原始文件。
- 如果你不确定消息的含义或因此应该在代码中更改什么，请使用帮助浏览器查找相关主题。

你也可以使用mlint函数获取M-Lint消息。关于此函数的更多信息，你可以在命令窗口中输入help mlint。阅读在线文档[3]了解关于此工具的更多信息。

### B.2.2 调试器

MATLAB编辑器、图形调试器和MATLAB调试函数对于纠正运行时问题很有用。它们使你能够访问函数工作区并检查或更改它们包含的值。你还可以设置和清除断点，断点是临时暂停文件中执行的指示器。在断点处停止时，你可以更改工作区上下文、查看函数调用堆栈并逐行执行文件中的代码。

调试中有两种重要技术：一种是断点，另一种是单步执行。设置断点来暂停函数的执行使你能够检查你认为问题可能所在位置的值。在调试时，你还可以单步执行M文件，在你想要检查值的点处暂停。

你可以在M文件中设置三种基本类型的断点：

- **标准断点**，在M文件中的指定行停止。
- **条件断点**，仅在指定条件下在M文件中的指定行停止。
- **错误断点**，当任何M文件产生指定类型的警告、错误或NaN或无穷大值时停止。

当MATLAB忙时（例如，正在运行M文件，除非该M文件在断点处暂停），你不能设置断点。当程序暂停时，你可以查看工作区中当前任何变量的值，从而允许你在想要查看一行代码是否产生了预期结果时检查值。如果结果符合预期，继续运行或单步到下一行。如果结果不符合预期，则该行或前一行包含错误。

在调试时，你可以更改当前工作区中变量的值，看看新值是否产生预期结果。当程序暂停时，在命令窗口、工作区浏览器或数组编辑器中为变量分配新值。然后继续运行或单步执行程序。如果新值没有产生预期结果，则程序有不同或另一个问题。

除了使用编辑器（这是一个图形用户界面）之外，你还可以通过使用命令窗口中的调试函数来调试MATLAB文件，或者你可以互换使用这两种方法。阅读在线文档[4]了解关于此工具的更多信息。

### B.2.3 分析器

分析是一种测量程序在执行各种函数上花费时间量的方法。使用MATLAB分析器，你可以识别代码中哪些函数消耗最多时间。然后你可以确定为什么要调用它们并寻找最小化其使用的方法。决定特定函数被调用的次数是否合理通常很有帮助。由于程序通常有多个层，你的代码可能不会显式调用最耗时的函数。相反，你代码中的函数可能调用其他耗时的函数，这些函数可能在代码中向下好几层。在这种情况下，确定你的哪些函数负责此类调用很重要。

分析有助于发现你可以通过以下方式解决的性能问题：

- 避免不必要的计算，这可能源于疏忽。
- 更改你的算法以避免昂贵的函数。
- 通过存储结果供将来使用来避免重新计算。

当你达到大部分时间花在调用少量内置函数上的程度时，你可能已经尽可能地优化了代码。你可以使用以下任何方法打开分析器：

- 从MATLAB桌面选择桌面 > 分析器。
- 从MATLAB编辑器/调试器的菜单中选择工具 > 打开分析器。
- 在命令历史窗口中选择一个或多个语句，右键单击查看上下文菜单，然后选择分析代码。
- 在命令窗口中输入以下函数：profile viewer。

要分析M文件或一行代码，在打开分析器后按照以下步骤操作，如图B.1所示：

1. 在分析器的"运行此代码"字段中，输入你想要运行的语句。
2. 单击开始分析（或在输入语句后按Enter键）。
3. 分析完成后，分析摘要报告出现在分析器窗口中。

阅读在线文档[5]了解关于此工具的更多信息。

## B.3 系统对象

系统对象是MATLAB中类的特化，它定义了一组特定的方法，使初始化、运行时操作和拆除变得简单。类本身基本上是一组共享一组称为参数的变量的函数。这些参数在类内定义并具有定义的作用域。虽然系统对象实现了许多方法，但用户应该理解的三个主要方法是setupImpl、stepImpl和releaseImpl。它们将被写为：

```matlab
methods (Access = protected)
    function setupImpl(obj)
        % 设置参数
        obj.x = 1;
    end
end
```

setupImpl用于初始化参数并执行系统对象生命周期所需的计算。stepImpl是运行时函数（方法），通常被多次调用，并将消耗或产生输入/输出。最后，releaseImpl用于拆除对象，这将清除其内存或执行关闭操作。例如，如果对象要将数据写入文件，它将在调用此方法时关闭文件。

当调用系统对象的运算符或step方法时，初始调用实际上会首先调用setupImpl方法。此时系统对象被认为已锁定。然后将调用stepImpl方法。连续的运算符或step调用将只调用stepImpl方法。要解锁对象，必须调用releaseImpl方法。一旦解锁，setupImpl将在下一次运算符或step调用时再次被调用。我们在这里用一个脚本概述这个过程：

```matlab
% 实例化对象
ss = dsp.SignalSource;
% 调用setupImpl和stepImpl
data = ss();
% 仅调用stepImpl
data = ss();
% 对象被解锁
ss.release();
% 调用setupImpl和stepImpl
data = ss.step();
```

系统对象对于封装大量功能以及需要维护状态时非常有用。例如，滤波器需要状态，是系统对象的明显用途。构成MATLAB的工具箱利用与其缩写相关的系统对象扩展。例如，来自通信系统工具箱的系统对象将具有扩展名comm，产生诸如comm.AGC、comm.CarrierSynchronizer或comm.EVM之类的对象名称。DSP系统工具箱中的示例有：dsp.FIRDecimator、dsp.SpectrumAnalyzer和dsp.SignalSource。关于系统对象的更多信息可以在MathWorks文档中找到，其中包含关于其实现和使用的广泛细节。
